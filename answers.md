Практическое занятие №12
Ответы на части A–F

Часть A. Базовый Python

1. Что такое переменная?
Переменная — это именованное место, где программа хранит значение.

2. Зачем переменной давать имя?
Чтобы обращаться к сохранённому значению по понятному имени.

3. Чем текст отличается от числа?
Текст состоит из символов, а число используется для вычислений.

4. Что такое логическое значение?
Это значение True или False — например, да или нет.

5. Для чего используется список?
Для хранения нескольких значений в одном наборе.

6. Для чего используется словарь?
Для хранения пар «ключ — значение».

7. Зачем нужны условия?
Чтобы программа выбирала действие в зависимости от ситуации.

8. Зачем нужны циклы?
Чтобы повторять действия несколько раз.

9. Что такое функция?
Функция — это отдельный блок действий, который можно вызывать по имени.

10. Что может получить функция и что может вернуть?
Функция может получить входные данные и вернуть результат.

Часть B. Модули и библиотеки

1. Что такое модуль?
Модуль — это обычно отдельный Python-файл с функциями, классами или данными.

2. Что такое библиотека?
Библиотека — это готовый набор возможностей для решения задач.

3. Зачем проекту нужны библиотеки?
Чтобы не писать всё с нуля и быстрее разрабатывать программу.

4. Что означает импортировать библиотеку?
Это значит подключить возможности библиотеки к программе.

5. Почему нельзя сказать, что любая библиотека уже является частью Python?
Потому что многие библиотеки устанавливаются отдельно и не входят в стандартный Python.

6. Что такое зависимость проекта?
Это внешний компонент или библиотека, от которой зависит работа проекта.

7. Почему важна версия библиотеки?
Потому что разные версии могут иметь разные возможности и правила работы.

8. Что может произойти при несовместимых версиях библиотек?
Могут возникнуть ошибки, сбои или неправильная работа программы.

9. Почему программисту выгодно использовать готовую библиотеку?
Это экономит время и уменьшает количество собственного кода.

10. Приведите два примера задач, которые разумно решать готовой библиотекой.
Обработка данных и работа с API.

Часть C. LLM-агент и инструменты

1. Что такое LLM-агент простыми словами?
Это система, в которой LLM понимает задачу и при необходимости использует внешние инструменты.

2. Что такое Tool?
Tool — это внешняя возможность, которую агент может вызвать для выполнения конкретного действия.

3. Зачем агенту нужны инструменты?
Чтобы получать данные и выполнять действия, которых нет у самой модели.

4. Кто принимает решение о необходимости вызвать Tool?
LLM выбирает подходящий Tool в зависимости от задачи.

5. Кто реально выполняет действие Tool?
Программа или подключённый сервис.

6. Зачем Tool нужны входные параметры?
Чтобы передать инструменту необходимые для работы данные.

7. Зачем Tool нужен результат выполнения?
Чтобы LLM могла использовать результат и сформировать ответ пользователю.

8. Зачем описывать ошибки инструмента?
Чтобы система понимала, что действие не выполнено, и могла корректно отреагировать.

9. Почему Tool должен иметь ограниченные права?
Чтобы уменьшить риск случайных или опасных действий.

10. Назовите пять возможных Tool для агента.
Калькулятор, поиск по файлам, база данных, API, планировщик.

Часть D. Мини-кейсы

1. «Посчитай 17% от 125 000»
Tool: Калькулятор.
Назначение: выполнить точный расчёт.
Вход: 125000 и 17%.
Выход: результат расчёта.
Если ошибка: сообщить об ошибке.

2. «Найди в документе раздел про требования к системе»
Tool: Поиск по файлам.
Назначение: найти нужный раздел документа.
Вход: документ и запрос пользователя.
Выход: найденный раздел и нужный текст.
Если ошибка: сообщить, что раздел не найден.

3. «Покажи статус обращения №5412»
Tool: Tool статуса обращений.
Назначение: получить текущий статус обращения.
Вход: номер обращения 5412.
Выход: текущий статус.
Если ошибка: сообщить, что обращение не найдено или сервис недоступен.

4. «Обработай пять загруженных документов»
Tool: Обработка документов.
Назначение: обработать загруженные документы.
Вход: пять документов.
Выход: результаты обработки.
Если ошибка: указать документ, который не удалось обработать.

5. «Проверь, есть ли свободное время для встречи»
Tool: Планировщик.
Назначение: проверить доступное время.
Вход: дата, время и длительность встречи.
Выход: свободно или занято.
Если ошибка: сообщить об ошибке календаря.

Часть E. Найдите ошибку в проектировании

1. Агент имеет полный доступ ко всей базе данных, хотя ему нужны только статусы обращений.
Ошибка: права слишком широкие.
Исправление: оставить только доступ к нужным статусам.

2. Агент вызывает калькулятор для каждого вопроса, даже когда расчёт не требуется.
Ошибка: инструмент используется без необходимости.
Исправление: вызывать калькулятор только при необходимости расчёта.

3. Инструмент не сообщает об ошибке, поэтому агент считает операцию успешной.
Ошибка: система не передаёт информацию о сбое.
Исправление: Tool должен возвращать понятный результат ошибки.

4. Один Tool одновременно читает файлы, удаляет данные, отправляет сообщения и меняет настройки.
Ошибка: один инструмент имеет слишком много функций и прав.
Исправление: разделить функции на отдельные инструменты и ограничить права.

5. Агент хранит результат, но нигде не фиксирует, какой версией модели он получен.
Ошибка: невозможно определить версию модели, которая создала результат.
Исправление: сохранять версию модели вместе с результатом.

Часть F. Соберите логику агента без кода

Ситуация: сотрудник спрашивает статус обращения №5412.

1. Запрос пользователя
Сотрудник спрашивает статус обращения №5412.

2. Что понимает LLM
Нужно узнать текущий статус обращения.

3. Какой Tool выбирается
Выбирается Tool для получения статуса обращения.

4. Какие данные передаются Tool
Передаётся номер обращения 5412.

5. Какой результат возвращается
Возвращается текущий статус или сообщение об ошибке.

6. Что проверяет LLM после результата
LLM проверяет, что результат получен корректно и без ошибки.

7. Что получает пользователь
Пользователь получает понятный текущий статус обращения.
